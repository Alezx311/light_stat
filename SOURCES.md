# Джерела для Києва

Перевірено 10 жовтня 2026 року. Сайт автоматично читає публічний канал «Підгрупи 6.2» (див. нижче). Автоматичного джерела фактичної історії для всіх будинків Києва немає.

| Джерело | Перевірена можливість | Рішення для Light Stat |
|---|---|---|

| [Angler](https://angler.com.ua/uk) | Карта, історія, ESP heartbeat. [Прошивка](https://github.com/UltraSkye/angler-esp) відкрита під MIT. | Відкритий bulk API, експорт та ліцензія міської бази не підтверджені. MIT прошивки не ліцензує дані сайту. |
| [ДТЕК](https://www.dtek-kem.com.ua/ua/shutdowns) | Адресна інформація і графіки; можливі різні вводи за однією адресою. | Авторитетне джерело графіків, але не безперервна історія вимірювань. |
| [YASNO](https://app.yasno.ua/) | Структуровані вебендпоїнти графіків; 10.10.2026 перевірено HTTP 200 і JSON для Києва. | Технічна доступність підтверджена. Шар графіків відкладений, фактичні години з нього не створюються. |
| [Київ Цифровий](https://kyivcity.gov.ua/news/u_miskomu_zastosunku_kiv_tsifroviy_zyavivsya_noviy_servis__stan_energosistemi/) | Адресні сповіщення та партнерські інтеграції. | Самостійний публічний потік фактичних подій не підтверджено. |

## Що змінилося за рік

- [SvitloBot 2.0 Android](https://play.google.com/store/apps/details?hl=en_GB&id=ua.svitlobot.v2): сторінка вказує оновлення 15 квітня 2026 року, моніторинг заряджання та явні повідомлення про його втрату. Це поліпшення збору, а не поява відкритого міського архіву.
- [Повідомлення Києва 2 лютого 2026](https://kyivcity.gov.ua/news/u_desnyanskomu_rayoni_z_3_lyutogo_zaprovadzhuyut_timchasovi_individualni_grafiki_vklyuchen_elektroenergi/): індивідуальні графіки будинків. Режим графіків змінюється; історичні групи не є незмінною міською адресною моделлю.
- [Умови Angler](https://www.angler.com.ua/en/terms) датовані січнем 2026 року; це не доказ дати запуску сервісу.
- [Стороння інтеграція YASNO](https://github.com/denysdovhan/ha-yasno-outages) описує машинні інтерфейси. Вона не є офіційним SDK чи гарантією доступності.

## Технічна перевірка YASNO

Під час початкового дослідження живий JSON не вдалося перевірити. Під час реалізації два одноразові GET-запити успішно повернули JSON:

~~~text
GET https://app.yasno.ua/api/blackout-service/public/shutdowns/addresses/v2/regions
GET https://app.yasno.ua/api/blackout-service/public/shutdowns/regions/25/dsos/902/planned-outages
~~~

Перша відповідь прямо визначила Київ як region id 25 і ПРАТ «ДТЕК КИЇВСЬКІ ЕЛЕКТРОМЕРЕЖІ» як dso id 902. Дніпро мав region id 3. Ідентифікатори потрібно отримувати з довідника, а не переносити з чужих прикладів.

Друга відповідь містила today / tomorrow, slots, date, status, updatedOn. Приклад на дату перевірки: ScheduleApplies для today, WaitingForSchedule для tomorrow; типи слотів Definite і NotPlanned. Це **графіки**, не вимірювання напруги. Навіть NotPlanned не означає підтверджене «світло є».

Одноразовий успішний GET не підтверджує SLA, ліцензію повторного використання, rate limit або право масового збору. Адаптер не вмикається автоматично. Відповіді перевірки збережено лише як локальні QA-артефакти в .cache/source-probes/.

## Умова підключення нового автоматичного джерела

Потрібні: доступний і дозволений спосіб читання історії, стабільний ідентифікатор точки, часові мітки подій, пояснений спосіб вимірювання, відомий термін актуальності та умови повторного використання. Публічна карта або відкрита прошивка окремо цих умов не виконують.

Покриття Києва та кількість активних датчиків SvitloBot / Angler не встановлені. Жодних приватних ключів не використано, звернень власникам сервісів не надсилалося. У цій версії немає фонових опитувань сторонніх API. Формат observations дозволяє додати законно отриманий експорт датчиків без змішування вимірювань і реконструкцій.
